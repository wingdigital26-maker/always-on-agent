Verdict

3 parts of the plan

The idea can be built. Three parts of the original plan should change before it touches real prospects: who holds the send button, what happens when a site blocks us, and how much we expect from a local model.

1
Works as planned

24/7 scraping, a database for facts, a vault for voice and judgment, and the UI running on the mini.

2
Works with a change

Local AI handles the bulk work. A cloud model takes the small share of hard calls.

3
Change it

No model holds the send key, and no model is told to beat a site's blocks.

Problems, ranked by damage

7 found
1
Severe

Scraped text can hijack an agent that can send

An agent with private data, outside text and a send path is the known "lethal trifecta." A hidden line on a web page or in a reply could steer it. Filters inside the model get beaten by adaptive attacks.

Fix

Split the powers. The reader sees raw text with no tools. The planner never sees raw text. Plain code checks every send.

2
Severe

A model rewriting itself past blocks creates legal exposure

On 31 July 2026 a court let Reddit's anti-circumvention claims against SerpApi and Perplexity proceed. Other rulings in this area are mixed, so the law is unsettled. An uncensored model also gets more dangerous when hijacked, and it gains little: repairing code seldom triggers refusals.

Fix

Use a standard model. It repairs scrapers when a page layout changes. A real block switches to a licensed source or pauses. Have a lawyer review the source list.

3
High

Fully automatic sends can burn the domain and create liability

Google's guidance is to stay below a 0.1% spam rate and never reach 0.3%. CAN-SPAM applies even to single commercial emails. Texts carry separate consent rules, so they are the riskiest channel.

Fix

Earn autonomy in steps (see the build order). First-touch cold messages stay human-tapped. Texting waits for legal review.

4
High

"Opus level on a Mac mini" is unproven

The strongest open models are very large; Kimi K3 is described as cluster-only. Machines this size run the 27B to 32B class, at a reported 18 to 38 tokens per second. Most scores come from the labs themselves. We could not confirm the two upcoming models.

Fix

Test on our own work. Run 50 real emails and 10 real scraper fixes through the local model and Claude, then grade them blind.

5
Medium

One box means one point of failure

A power cut, a dead disk or a bad update stops everything. Memory is a hard wall too: once a model spills to swap, one guide reports speed falling from 15 tokens per second to 1.

Fix

Battery backup, nightly off-site backups, automatic restart, and a job queue so one heavy model runs at a time.

6
Medium

"Zero usage" covers only the model

Data APIs, skip tracing, email tools, proxies, domains and power all still cost money. The hardware has a price too. The real saving is the AI bill, and it grows with volume.

Fix

Track cost per qualified lead from day one, so the comparison with cloud AI is a measured number.

7
Medium

The vault can get poisoned or swamped

Your split is right: database for facts, vault for judgment. The risk is scraped text or bad lessons landing in the file that sets the agent's behavior.

Fix

The agent proposes vault changes and a person approves them. Keep the vault in version control so any change can be rolled back.

How to make it better

6 upgrades

Keep models swappable

Put every model behind one internal endpoint. When a better one ships, it runs the same blind test and replaces the old one with no rebuild.

Use two model sizes

A small fast model sorts and extracts all day. The large one wakes only for drafts and decisions, which saves memory and time.

Score every data source

Track which sources produce replies and deals, then drop the rest. Scraping less and better beats scraping everything.

Learn from outcomes

Feed replies, edits and rejected drafts into proposed vault updates. A weekly review approves what the agent learned.

Send a morning brief

One page: what it found, sent and fixed, what it spent, and what needs a decision. This is what people will actually read.

Add a hard stop

Automatic pause on a bounce or complaint spike, plus daily send and spend caps. One button stops everything from a phone.

Extending it to Roof Command

One change

Yes, with one change: a monitor across all clients, while each client's data stays walled off. Customer apps should stay on hosted infrastructure, because a closet machine going down shouldn't take a paying roofer offline. The mini does the thinking in the background.

The monitor can restart a failed job by itself. Anything a roofer or homeowner would see goes to a person first.

We have a head start here. The Sentinel health checks, reply triage, Scrapling, Deal Desk and Wing Outreach already exist, so most of the first version is wiring, not new product.
